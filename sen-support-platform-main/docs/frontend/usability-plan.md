# План юзабилити-тестирования

| Пункт | Описание |
|---|---|
| **Цель** | Проверить, что родители и специалисты без подсказок выполняют ключевые задачи и понимают режимы видимости и согласия |
| **Что тестируем** | Кликабельный прототип (демо в `/frontend`), позже - реализованные экраны |
| **Участники** | Пять участников: два родителя, два специалиста и один администратор/координатор; планируемая удобная выборка. Приглашать только людей, заранее согласившихся на участие; реальные каналы набора фиксировать после согласования |
| **Условия** | Сессия 20-25 минут; смартфон или ноутбук по выбору участника; модератор не подсказывает; запись экрана только с согласия |
| **Когда** | После предзащиты, на прототипе; повторно - на реализованных экранах |
| **Задачи** | 1) Родитель: зарегистрироваться и сохранить демонстрационный профиль ребёнка; согласие в макете является иллюстративным и не заменяет утверждённый правовой процесс. 2) Родитель или специалист: добавить занятие в расписание. 3) Специалист: создать запись «только специалистам». 4) Родитель или администратор: найти запись о просмотре данных ребёнка |
| **Метрики** | Доля успешно выполненных задач; время на задачу; число ошибок и обращений за помощью; оценка по шкале SUS; комментарии |
| **Критерии успеха** | Не менее 80% назначенных задач выполнены без подсказки; SUS ≥ 68; ни одной критической ошибки в задачах про видимость и демонстрационное согласие. Это критерии будущего теста, а не полученные результаты |
| **Базовое решение для сравнения** | Текущий способ участника (например, мессенджер, таблица или тетрадь) записывается только с его слов; сравнение не подменяет результаты usability-теста |
| **Фиксация результатов** | Таблица «участник × задача», список проблем с серьёзностью (низкая / средняя / высокая); правки вносятся в прототип и требования |
| **Связь с проверкой безопасности** | Доступность и безопасность проверяются по плану верификации команды. Здесь мы смотрим только, понятны ли людям режимы видимости и согласие |
